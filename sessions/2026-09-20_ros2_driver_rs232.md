## Package: `ros2/rob3_driver/` (ament_python)

Layered so the protocol core is testable without ROS:

- **`rob3_driver/protocol.py`** — pure wire-protocol codec (no ROS/serial deps).
  Encodes the verified command set (startup `0x20` handshake; set/query position
  single+all; position+speed; motor enable/disable/e-stop; serial number), all
  ETX-framed; parses replies; classifies the `0xFx` ACK/status family (not
  errors). Provenance-annotated.
- **`rob3_driver/transport.py`** — `SerialTransport` (pyserial, real
  `/dev/ttyUSB0`, 9600 8N1) and `TcpTransport` (ucSim `-S` socket) behind one
  interface, so the driver runs against HW or the simulator unchanged.
- **`rob3_driver/calibration.py`** — per-axis joint(rad/m) ↔ 0..255 count map
  from the documented joint ranges; clamps counts (firmware has no soft limits).
  Endpoint counts/direction are bench placeholders to verify.
- **`rob3_driver/rob3_interface.py`** — `Rob3Client` = codec + transport
  (connect/handshake, move, query, control).
- **`rob3_driver/rob3_driver_node.py`** — ROS 2 node: `/joint_states` (polled via
  `0x4F`), a `FollowJointTrajectory` action (streams per-axis setpoints), and
  `Trigger` services enable/disable/estop/read_serial_number. Degrades
  gracefully if the transport can't open.
- **`urdf/rob3.urdf.xacro`** (6 revolute axes + prismatic gripper, documented
  limits), **`launch/rob3.launch.py`**, **`config/rob3_controllers.yaml`**,
  `package.xml`/`setup.py`/`setup.cfg`/`resource`.

## UR-driver parallel

## Environment / ROS distro

- **No ROS 2 in this environment** (no `/opt/ros`, no `rclpy`/`control_msgs`/
  `sensor_msgs`, no `ros2` CLI). So the **node/launch/action/services cannot be
  run here** — only `py_compile` syntax-checked. pyserial 3.5 IS present.
- The package is written **distro-agnostic** across the Python-based LTS distros
  (ament_python; rclpy ActionServer/MultiThreadedExecutor/ReentrantCallbackGroup;
  JointState/Trigger/FollowJointTrajectory/Duration — all API-stable Foxy→
  Rolling). Chose a plain driver node over a ros2_control SystemInterface partly
  because the hardware-component API has shifted across distros.
- **Docs/examples default to Humble + Jazzy.** No installed distro was targeted
  (couldn't be, with no ROS here). To pin a specific distro: verify the exact
  `control_msgs` FollowJointTrajectory.Result constant names against it and set
  `package.xml`/README accordingly. TARGET DISTRO NOT YET CHOSEN by the user.

## Corrections / findings

- `query_all_positions` initially emitted `0x47` (0x40|0x07); the manual
  documents `0x4F` (adds bit3). Both read all axes in the ROM, but the codec now
  emits the documented `0x4F`. (Caught by a unit test.)
- The fake-transport test initially mis-classified ack-bit headers (0x0A);
  fixed the fake to mask the class nibble — a test-harness bug, not driver code.
