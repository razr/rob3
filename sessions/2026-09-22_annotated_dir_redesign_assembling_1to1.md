## 2. Seven subsystem `.inc` files replace the monolithic `rob3.inc`

```
inc/
  sfr.inc         8051 SFRs + bit addresses (architecture)
  devices.inc     MOVX device windows (8255 / ADC / SRAM) — ADC stays here (option b)
  system.inc      ★ AUTHORITATIVE IRAM map (0x00–0x7F) + shared flag bytes
                  (0x20 system, 0x23 timer, 0x28 state) with per-bit defs
  servo.inc       per-axis arrays + masks (0x21/0x22/0x2B/0x2C/0x2D)
  teachbox.inc    keypad/editor (0x46/0x47/0x56/0x57/0x29/0x2A)
  serial.inc      RS-232 workspace (0x24/0x25/0x60/0x68) + protocol constants
  program.inc     interpreter (0x3E/0x3F/0x66/0x67/0x26/0x27) + opcodes
```

`system.inc` documents the full 0x00–0x7F IRAM layout and defines every
documented bit of the cross-cutting flag bytes with `_Bn` equates and provenance
tags. No duplicate symbols across the seven includes (verified). No standalone
`adc.inc` — the ADC has no data structures, only MOVX windows (devices.inc) and
feedback array (servo.inc).

## 4. Byte-exact conversion using disasm51

Installed [disasm51](https://github.com/OlekMazur/disasm51) 1.0.2 (the same
decoder that produced `firmware/src/main.asm`) in a venv (`pip install disasm51`,
env is externally-managed).

Wrote `d51_to_sdas.py`: uses `disasm51.instructions.Instructions` to decode a
ROM region and emit sdas8051-native syntax (0x.. hex, numeric bit addresses,
in-region branch targets as local labels, out-of-region/absolute targets as
numeric). This is the authoritative decode — same opcode table as the original
disassembly.

Converted all 10 regions:
- **vectors, ext0_estop, timer0_tick, tables** — hand-written with symbolic
  equates from the inc files (small, already annotated, encode verified first).
- **ext1_servo, rs232, init, main, program, teachbox** — bodies generated by
  `d51_to_sdas.py`, preserving the existing annotation headers as structured
  comments above the assembling body.

Each region verified individually (`make verify-region`), then the whole image:

## 6. Corrections / findings

- **RS-232 region extends to 0x0587** (not 0x052F): the TX helper at 0x0541
  continues past the ISR/dispatch end, with a short 0xFF gap at 0x0530–0x053A.
  Truncating at 0x052F leaves 77 non-FF bytes unaccounted for — the whole-image
  `cmp` caught this immediately (first diff at byte 1340 = 0x053C). [BYTE]
- **Program interpreter starts at 0x0800** (not 0x0803): a 3-byte `prog_init`
  stub (`30 41 7D` = `JNB 0x28.1, ...`) that init `LCALL`s. [BYTE]
- **Dead data at 0x0020** (`00 12 22`): non-0xFF bytes in the Timer 1 vector
  gap, never executed. Must be emitted explicitly (`.db`) since objcopy
  gap-fill only writes 0xFF. [BYTE]
- **sdas8051 rejects disasm51 dialect**: `NNh` suffix, `28h.7` bit dot-notation,
  bare `org`, `$` self-ref — all fail. The converter handles this; old annotation
  headers with pseudo-instructions were commented out.
- **sdas8051 `.org` gap behavior**: the assembler emits only the bytes you
  define; `objcopy --gap-fill=0xFF` fills the rest. No need for explicit `.db
  0xFF` padding runs between regions.
