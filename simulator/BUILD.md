# BUILD

How to verify and behaviorally test the ROB3 firmware.

This build/verify/simulate rig lives in the top-level `simulator/` directory and
reads the ROM image and annotated sources from `../firmware/`. For toolchain
prerequisites see [`../firmware/INSTALL.md`](../firmware/INSTALL.md).

## TL;DR

```bash
cd simulator
make verify     # golden byte-match: assembled annotated source == the real ROM
make test       # golden byte-match + simulator behavioral tests
```

## What this build does

The annotated disassembly under `../firmware/src/annotated/` documents the
firmware at the instruction level. To prove that documentation is faithful — and
that the firmware actually behaves as annotated — verification has two
independent halves:

1. **Golden byte-match (A).** The annotated source is an *assembling* 1:1
   transcription of the ROM: `../firmware/src/annotated/` builds the whole 8 KB
   image and `cmp`s it against `../firmware/bin/M2764A@DIP28.BIN`. This proves
   *the listing matches the firmware image*. This directory's `make verify`
   **delegates** to that tree (`make -C ../firmware/src/annotated verify`).

2. **Simulator behavioral tests (B).** The **real ROM**
   (`../firmware/hex/M2764A@DIP28.HEX`) is run in ucSim (`s51`) and its runtime
   state is checked against the annotation's claims. This proves *the firmware
   behaves as documented*.

> **History:** the golden check previously used per-region `.a51` `.db`
> transcriptions (`init.a51`, `teachbox_scan.a51`) generated by `gen_init.py`.
> Those were removed once the annotated tree became the single assembling 1:1
> source; the golden test now covers the *whole* ROM, not just two regions.

## Layout

```
rob3/
├── firmware/
│   ├── INSTALL.md               # toolchain prerequisites
│   ├── bin/M2764A@DIP28.BIN     # ROM image (binary)  — golden reference
│   ├── hex/M2764A@DIP28.HEX     # ROM image (Intel HEX) — loaded by the simulator
│   └── src/
│       ├── main.asm             # raw disasm51 output
│       └── annotated/           # ASSEMBLING 1:1 annotated source (+ Makefile)
│           ├── rob3.asm         #   top unit: includes inc/*.inc + all regions
│           ├── vectors.asm ... teachbox.asm   # one file per functional region
│           └── inc/*.inc        #   symbolic equates (sfr/devices/system/servo/...)
└── simulator/
    ├── Makefile                 # behavioral tests + delegated golden verify
    ├── BUILD.md                 # this file
    ├── build/                   # (generated) rob3.hex + sim scratch
    ├── ucsim-modules/           # loadable cl_hw plugins (teachbox/adc/loopback/rxd)
    └── tests/                   # behavioral test scripts (sim_*.sh, *.py)
```

## Make targets (simulator/)

| Target | Description |
| :----- | :---------- |
| `make` / `make all` | Run `test` (golden + behavioral). |
| `make verify` | **Golden test** (delegated): assembled annotated source == ROM. |
| `make sim-init` | Behavioral: init stalls at `0x0680` (ADC EOC/INT1 wait). |
| `make sim-run` | Behavioral: inject the gates, run to end of init `0x074B`. |
| `make sim-serial` / `sim-program` | Behavioral: RS-232 dispatch / stored-program interpreter. |
| `make sim-teachbox` | Behavioral: keypad scanner decode (P1 injection). |
| `make sim-teachbox-module` / `sim-adc` | Behavioral: compiled cl_hw modules (opt-in). |
| `make test` | `verify` + all behavioral tests. |
| `make clean` | Remove `build/`. |
| `make help` | List targets. |

The golden build itself (in `../firmware/src/annotated/`) has its own targets:
`make verify`, `make regions` (dump each region's ROM slice), `make status`
(report regions not yet byte-complete). See that directory's `README.md`.

## Toolchain pipeline (golden)

```
firmware/src/annotated/rob3.asm --sdas8051--> rob3.rel --sdld--> rob3.ihx --objcopy--> rob3.bin (8 KB)
                                                                                          |
                                                     cmp against firmware/bin/M2764A@DIP28.BIN
                                                                                          v
                                                                              GOLDEN PASS/FAIL
```

Overridable variables (e.g. macOS `gobjcopy`):

```bash
make -C ../firmware/src/annotated OBJCOPY=gobjcopy verify
make SIM="$(command -v s51)" test
```

## What the tests assert (and why)

### Golden (`verify`)
The assembled annotated source must be **byte-identical** to
`../firmware/bin/M2764A@DIP28.BIN` across the whole 8 KB image. Matching
SHA-256 hashes are printed as proof.

### Behavioral (`sim-init`, `sim-run`, ...)
These run the real ROM in ucSim and check runtime state against the annotation:

- **`sim-init`** — from reset, init **blocks at `0x0680`** waiting for the ADC
  end-of-conversion (`EOC → INT1`). On a *stock* `s51` with no ADC model this
  stall is the expected, correct behavior.
- **`sim-run`** — injects the missing hardware stimuli (an ADC-EOC/INT1 toggle
  and forcing `P3.0=0` for the fixed-baud path) so init runs to completion at
  `0x074B` with the axis speed table seeded.

The injected stimuli are **test scaffolding**, not claims about the silicon.
The `cl_adc` loadable plugin in `ucsim-modules/adc/` replaces this scaffolding
with a real ADC/EOC model so the ROM can free-run; see that module's README.
Full per-test detail — every assertion, the injection mechanics, how to run a
test standalone, and how to read failures — lives in
**[`tests/README.md`](tests/README.md)**.

## Scope & limitations

- Stock ucSim models the MCS-51 core only; external peripherals (8255, ADC,
  SRAM, 74LS138 decode) are **not** modeled, which is why the behavioral tests
  are structured around the hardware-dependent gates. The `ucsim-modules/`
  peripherals (teachbox, adc, loopback, rxd) add those models as loadable
  plugins (`loadhw`) to a ucSim built with the plugin loader.

## Manual simulator poking

Load the ROM and explore interactively:

```bash
cd simulator
cp ../firmware/hex/M2764A@DIP28.HEX build/rob3.hex
s51 -t 51 -X 11.0592M build/rob3.hex
# then, at the uCsim prompt:
#   reset
#   pc 0x0600
#   dc 0x0600 0x074c      ; disassemble init
#   break 0x0680          ; the ADC/INT1 gate
#   run
#   dump sfr 0xa8 0xa8    ; IE
#   dump iram 0x20 0x2f
#   quit
```
