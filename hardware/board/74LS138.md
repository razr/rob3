# 74LS138

The 74LS138 is a 3-to-8 decoder used to generate the board's chip-select signals for memory and peripheral devices.

## Pinout

```text
                       TOP VIEW
                     +-----U-----+
      A (LSB) input ─| 1      16 |── VCC (+5V)
       B input      ─| 2      15 |── Y0 (active LOW)
       C input      ─| 3      14 |── Y1 (active LOW)
   G2A (active LOW) ─| 4      13 |── Y2 (active LOW)
   G2B (active LOW) ─| 5      12 |── Y3 (active LOW)
   G1 (active HIGH) ─| 6      11 |── Y4 (active LOW)
    Y7 (active LOW) ─| 7      10 |── Y5 (active LOW)
       GND          ─| 8       9 |── Y6 (active LOW)
                     +-----------+
```

## Board connections

```text
                              +-----U-----+
    pins 1, 11 tied together ─| 1      16 | +5V
                EPROM pin 23 ─| 2      15 | GND
                  SRAM pin 2 ─| 3      14 | 8031 pin 27
                          NC ─| 4      13 | 74HC14 pin 1
         74HC14 pins 4 and 5 ─| 5      12 | EPROM pin 20
                  8255 pin 6 ─| 6      11 | pins 1, 11 tied together
                  ADC pin 22 ─| 7      10 | NC
                         GND ─| 8       9 | NC
                              +-----------+
```

## Notes

- The active-low outputs match the board's memory selection scheme.
- It is the main address decoder for selecting EPROM, SRAM, and peripheral interfaces.

## Decode logic (derived from board + firmware)

The three select inputs are **not** three plain CPU address lines:

- **B (pin 2) = A11** — driven from the CPU high-address bus (EPROM pin 23 / 8031 pin 24).
- **C (pin 3) = A12** — driven from the CPU high-address bus (SRAM pin 2 / 8031 pin 25).
- **A (pin 1) is tied to Y4 (pin 11)** — an intentional self-feedback. `A` is therefore
  **not** a CPU address line; it is driven by the decoder's own Y4 output. Because
  Y4 is active-LOW and feeds back into `A`, the {Y4,Y5} pair forms a self-consistent
  latched state rather than a fresh address decode. The register-level distinction
  *inside* a selected block is made by the peripheral itself (the 8255's own A0/A1,
  or the ADC's A8/ADD-A channel line), not by this `A` input.

The high-order lines **A14/A15** gate peripheral space vs external-SRAM space
(all peripheral `DPH` values have A14=1, A15=0; the SRAM window uses A15=1, A14=0).
`8031 pin 27` (A14) participates on the decoder enable/gating side, not as an output.

### DPH -> decoder region -> device

Firmware selects devices by writing `DPH` (high address byte) before `MOVX @DPTR`.
With B=A11 and C=A12 as the real CPU selects, the observed `DPH` values map as:

| DPH        | A12 (C) | A11 (B) | Region  | Device                         | Board pin |
| :--------- | :-----: | :-----: | :------ | :----------------------------- | :-------- |
| 0x48       |   0     |   1     | Y2 / Y3 | aux / axis-select latch        | Y2 (pin 13) -> 74HC14 pin 1; Y3 (pin 12) -> EPROM pin 20 |
| 0x50..0x53 |   1     |   0     | Y4 / Y5 | 8255 PPI (A0/A1 pick the port) | G1 enable (pin 6) -> 8255 pin 6 |
| 0x58, 0x59 |   1     |   1     | Y6 / Y7 | ADC / axis feedback            | Y7 (pin 7) -> ADC pin 22 |

- `0x50` vs `0x51/0x52/0x53` are the four 8255 registers, resolved by the 8255's own
  A0/A1 (8255 pins 8/9), **not** by this decoder.
- `0x58` vs `0x59` differ only in **A8**, which is the ADC channel-select line
  (ADD A). This is consistent with only ADD-A being CPU-driven on the ADC
  (ADD B/ADD C are strapped) — see `adc.md`.

> Open item: the exact G1/G2A/G2B source that produces the A14=1 / A15=0 peripheral
> gate is only partially ringed out (G1 pin 6 <- 8255 pin 6, G2B pin 5 <- 74HC14
> pins 4/5, G2A pin 4 = NC). The A11/A12 select decode above is confirmed; the
> enable-side gating expression should be re-verified against the physical board.

## Reverse-engineering relevance

This decoder defines the board's memory map. The 8031 binary is effectively a sequence of address writes and decode events that select different blocks of the board.

For firmware analysis, the key question is not only which IC is connected, but which output line is active for a given address. That line tells you which device the program is addressing at any moment, and therefore which code, data, or control register is being touched.
