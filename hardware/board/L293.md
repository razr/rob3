# L293

The L293D is a dual H-bridge driver used to control the robot's DC motors. It takes the 8031/8255 logic signals and translates them into drive outputs capable of switching motor current direction and braking.

## Pinout

```text
               TOP VIEW
                      +---U---+
     1,2EN (Enable 1) | 1    16 | VCC1 (+5V logic)
       1A (Input 1)   | 2    15 | 4A (Input 4)
       1Y (Output 1)  | 3    14 | 4Y (Output 4)
                GND   | 4    13 | GND
                GND   | 5    12 | GND
       2Y (Output 2)  | 6    11 | 3Y (Output 3)
       2A (Input 2)   | 7    10 | 3A (Input 3)
      VCC2 (motor)    | 8     9 | 3,4EN (Enable 2)
                      +-------+
```

## Board connections

- L293 #1 is wired to 8255 Port A and the first motor pair.
- L293 #2 continues the same Port A pattern for the second motor pair.
- L293 #3 is wired to Port C for the remaining motor lines and enable logic.
- The chip outputs are routed to the board's motor connectors and feedback lines.
- Pin 9 (3,4EN / Enable 2) is tied to VCC (+5V) on each populated L293.

Based on your assembly code, your three L293D motor driver chips are mapped through your 8255 Peripheral Interface (PPI) via Port A (5000H) and Port C/Control (5200H).
Because an L293 is a dual H-bridge chip, controlling 3 of them requires up to 12 direction inputs (4 lines per chip) and 6 enable lines (2 lines per chip). 
Your code uses the 8-bit ports of the 8255 to control them simultaneously via memory-mapped loops.

The register mapping inside your software works as follows:

## ⚙️ The Driver Code Layout
### 1. The Motor Selection Loop (01A5H – 01B9H)

The code initializes the data pointer high byte (DPH) to target the I/O block specifically linked to the motor ports

```asm
jump_01A5:
	mov 83h, #50h	; Sets DPH = 50h (Points to 5000h)
	mov R1, #4Eh	; Points R1 to RAM state mirror byte
	sjmp jump_01B9  ; Jumps directly into the execution loop
```

- Address 5000H (DPH = 50H): This corresponds directly to 8255 Port A. In your hardware, this port is wired directly to the Logic Inputs (IN1 to IN4) of the first two L293D chips (controlling the primary direction phases).
- Address 5200H (DPH = 52H): Shifting the pointer to 52H switches the output target to 8255 Port C. This port is wired to the remaining direction inputs of the third L293D chip and the master Enable pins (1,2EN and 3,4EN) to switch individual motors on or off.

## 2. The Direction Strobe Routine

Once the processing loops lock onto a desired direction state, the software updates the physical pins using back-to-back external memory outputs

```asm
	mov 83h, #50h	; Target 8255 Port A (Address 5000h)
	mov A, 4Eh      ; Load calculated direction bits for Motors 1-4
	movx @DPTR, A   ; Send bits out through the pins of L293D Chips #1 and #2

	mov 83h, #52h	; Target 8255 Port C (Address 5200h)
	mov A, 4Fh      ; Load calculated direction/enable bits for Motors 5-6
	movx @DPTR, A   ; Send bits out to activate Chip #3 and Enable rails
```

## 🗺️ Physical Interfacing on the 3 Chips

Since each L293D controls 2 standard DC motors, your 3 chips form a 6-axis motor drive block handled natively by the 8255 parallel outputs.

-------------------------------------------------------------------------
Port A (5000H) Bits 0–3     | L293D Chip #1 Inputs (1A, 2A, 3A, 4A) | Motors 1 & 2 (Direction Phase A/B)
Port A (5000H) Bits 4–7     | L293D Chip #2 Inputs (1A, 2A, 3A, 4A) | Motors 3 & 4 (Direction Phase A/B)

Port C (5200H) Upper Bits   | All Chips' Master Enable Pins (EN1, EN2) | Safety ON/OFF cutoff gating for all 3 drivers.

## 🗺️ The Position Feedback Memory Map

Your 8031 code reads your motor position sensor lines by accessing 8255 Port B (5100H) and storing the values in internal RAM.

### 1. The Position Status Mirror Area

Your assembly file dedicates a structured block of consecutive registers inside the internal RAM (addresses 50H through 55H) to store the position of each of your 6 motors:
- 50H → Motor 1 Position
- 51H → Motor 2 Position
- 52H → Motor 3 Position

Yes, the inputs you are seeing are absolutely connected to the L293D chips as well!
In closed-loop motor systems from the 1990 era, it is a very clever hardware configuration. The position signals must go to both the L293D drivers and the 8255 interface simultaneously for the circuit to function correctly

### 1. Dual-Routing: Why They Connect to Both Chips

The tracking line from each motor sensor splits on the circuit board and runs to two different destinations:
- To the 8255 Inputs: Connected here so your 8031 program can read the real-time position state. The assembly logic checks these bits to calculate if a motor has reached its location target.
- To the L293D Enable/Input Pins: Tied directly to the driver chips to create an instantaneous hardware safety override cutoff.

### 2. How the Hardware Overrides the Software

If the position input is acting as an absolute limit switch, wiring it straight back into the L293D provides a crucial physical fallback layer:
- The Problem with Software Alone: Microcontrollers like the 8031 can occasionally freeze or lag in a long code routine. If a motor hits a physical wall while the code is stuck, it will strip the gears or burn out the L293D.
- The Hardware Solution: By routing the position input switch directly to the L293D Enable pins (1,2EN or 3,4EN), the physical contact switch will cut power to the motor instantly. The motor will stop on a dime at the hardware level, regardless of what the 8031 microprocessor is doing.
